**Partial result (AC, direction: disproof). Nothing here proves or disproves the Andrews–Curtis conjecture or
Stable AC; no disproof is claimed.**

**Setting.** We work in the SAIR ACC 14-move model (`ac-r2-v1`) on the two unresolved length-14 Miller–Schupp
presentations P1 = ac-02089 = MS(2, x⁻²y⁻¹x²y) and P2 = ac-08126 = MS(2, x⁻²y⁻¹x²y⁻¹), with AK(3) = ac-00399 and the
residual classes C3, C4, C6 of nahomar/andrews-curtis-solver. Peak = maximum total relator length along a ledger.

**Prior result used (cited).** SAIR Proof Track submission ACC-P000012 (2026-09-30; the ms14 project,
github.com/alejandrozarco/andrews-curtis-ms14, Zenodo 10.5281/zenodo.23196602) certified P1 ~ C6 (1066 moves, peak 41)
and exhaustively enumerated the capped components of P1 and P2 up to total length 32; no component contains AK(3), the
trivial presentation or the other start, so in that search model every AC path from P1 or P2 to AK(3)/trivial/each other
reaches peak ≥ 33. It labels the enumerations "computational, not independently verified".

**Our contribution.**
1. *Independent verification.* A second implementation, written from the published search semantics with no shared code
with the ms14 engine, reproduces every published capped-component count digit-for-digit (P1 caps 24/29/30/31/32; P2 caps
24/29/30/31/32; AK(3) cap 26 — including P1 cap-32 = 32,699,098 and P2 cap-32 = 71,499,215, with levels and length
histograms), all six nahomar rotation-only cap-28 counts, and the ms14 Q/E model cross-checks (Q at cap 24: 17,718 P1
classes and 21,932 P2 classes, zero difference; E at cap 20: 1,219,064 P1 and 696,024 P2 exact states projecting onto
473 and 521 classes, all inside the enumerated components). The 1066-move P1~C6 ledger is regenerated byte-for-byte.
2. *Cap-33 extension (the new result).* Complete enumeration of the cap-33 components (conjugator bound K = 9, the
published completeness condition K ≥ floor((33−14)/2)):
   - P1 = ac-02089: states = 94,705,057, levels = 448, complete = 1; the only target met is C6 (the known link).
     Hence every SAIR AC path from ac-02089 to ac-00399, to ac-08126, or to the trivial presentation has peak ≥ 34.
   - P2 = ac-08126: states = 235,809,128, levels = 457, complete = 1; **no** target (AK(3), P1, trivial, C3, C4, C6)
     is met. Hence every SAIR AC path from ac-08126 to ac-00399, to ac-02089, to the trivial presentation (and to
     C3/C4/C6) has peak ≥ 34.
     Both runs were replicated exactly by the second implementation (identical state counts, level counts, complete
     flags, length histograms and hit sets), so the two bounds `B(P1,AK(3)) ≥ 34`, `B(P2,AK(3)) ≥ 34` are held to the
     same standard as the published counts.
3. *Machine-checkable closure certificate.* For AK(3) at cap 28 (8,694,374 classes) we provide a standalone-checkable
   closure certificate: a sorted 128-bit class-key file plus a checker that re-generates all capped moves from scratch
   (238,806,300 moves checked, 0 violations), verifies the start class is present and the trivial presentation absent,
   certifying `B(AK(3)) ≥ 29` without re-running the search.
4. *New certificates.* P1 ~ φ₁(C6) (461 moves, peak 49) and C6 ~ φ₁(C6) (1920 moves, peak 43), φ₁: x ↦ x⁻¹; all
   certificates in the repository replay under the official `verifier.core.apply_move`. (These do not improve the
   shortest known P1~C6 ledger; P1 ~ φ₁(C6) is not a certificate for P1 ~ C6.)

**Model caveat.** The implication from an exhausted capped component to "no SAIR path with peak ≤ 33" uses the
projection/completeness argument documented in the ms14 repository (exact state (a u a⁻¹, b v b⁻¹) ↦ {u,v}; a
multiplication projects to the bounded-conjugator move; K ≥ floor((L−m)/2), m = 14). We independently re-ran the ms14
small-cap Q/E cross-checks of that model (PASS, matching the published numbers), but the argument is not formalized in a
proof assistant here.
