# Independent verification and a cap-33 extension of the length-14 Andrews–Curtis bounded components

**Status**: local technical report (round 3, 2026-11-12). Not submitted anywhere. **Partial computational result — it does not prove or disprove the Andrews–Curtis conjecture or Stable AC.**
**Scope**: SAIR ACC 14-move model (`ac-r2-v1`) through the capped quotient search model documented in the ms14 repository (alejandrozarco/andrews-curtis-ms14, Apache-2.0, AI-generated, not peer reviewed).

## 1. Setting and definitions

Balanced rank-2 presentations `P = <x,y | r1=1, r2=1>`; SAIR ACC moves: invert a relator (0/1), multiply it by the other relator or its inverse (2–5), conjugate it by `x, x^{-1}, y, y^{-1}` (6–13). Relators are kept freely reduced. The target is the exact ordered pair `(x,y)`.

`B(P,Q)` := infimum over AC-equivalence ledgers from `P` to `Q` of the maximum total relator length along the ledger (the **peak**); `B(P) := B(P, <x,y|x,y>)`.

Length-14 residual presentations (Carreras/nahomar/ms14 numbering; SAIR ids in parentheses):
- `P1 = MS(2, x^{-2}y^{-1}x^2y)` = ac-02089 (words `XyyxYYY|XXXYxxy`),
- `P2 = MS(2, x^{-2}y^{-1}x^2y^{-1})` = ac-08126 (`XyyxYYY|XXXYxxY`),
- `AK(3) = <x,y | x^3=y^4, xyx=yxy>` = ac-00399 (`xxxYYYY|xyxYXY`),
- residual classes `C3, C4, C6` of nahomar/andrews-curtis-solver (e.g. `C6 = <x,y | x^2yx^2y^{-2}, xyx^{-1}y^{-2}x^{-1}y>`).

**Search model (ms14).** States are unordered pairs of nonempty cyclically reduced words modulo rotation and inversion of either relator, swapping, and the 8 signed letter permutations. A move replaces one relator by the cyclic reduction of
`rot_i(u) · c · rot_j(v^{±1}) · c^{-1}`,
`c` a reduced word; for `c = 1` all rotations `i, j` are used; for `|c| ≥ 1` only junction-free `c` (other `c` reduce to shorter ones with other rotations/inversions). Only states of total length `≤ L` are kept. The completeness condition for the projection argument is `K ≥ floor((L-m)/2)`, `K` the conjugator bound, `m` the minimal total length in the component (`m = 14` here).

## 2. Main results (model-relative)

**(A) New bounds.** In the SAIR 14-move model, with `L = 33`, `K = 9` (satisfying the completeness condition for `m = 14`):
```
B(P1, AK(3)) >= 34,   B(P1, P2) >= 34,   B(P1) >= 34,
B(P2, AK(3)) >= 34,   B(P2, P1) >= 34,   B(P2) >= 34,
```
and moreover (from the same two runs) `B(P1, C6) >= 34` is *not* claimed (C6 is reachable from P1 within peak 32 — the one hit of the P1 run), while `B(P2, C6) >= 34`, `B(P2, C3) >= 34`, `B(P2, C4) >= 34` hold. The published predecessor (ACC-P000012 / ms14, 2026-09-30) proved `>= 33`; this is a one-cap extension, computed independently and cross-checked.

**(B) Independent verification.**
- A second implementation (`code/ms14_engine.cpp`, written from the published semantics; no shared code with the ms14 engine) reproduces the P1 cap-33 run exactly: same `states = 94,705,057`, same `levels = 448`, same complete flag, same length histogram, same hit set. It also reproduces the published capped-component counts 11/11 (P1 caps 24/29/30/31/32, P2 caps 24/29/30/31/32, AK(3) cap 26) and the six nahomar rotation-only cap-28 counts. The P2 cap-33 replication is recorded in the repository.
- The ms14 Q/E model cross-checks were re-run independently (Q: independent Python quotient implementation vs the acsearch dumps at cap 24 for P1/P2 — 17,718 / 21,932 classes, zero difference; E: SAIR `verifier.core.apply_move` exact-graph projection at cap 20 — 1,219,064 / 696,024 exact states projecting onto 473 / 521 classes, all inside the acsearch components, zero missing). The numbers match the published crosscheck results.
- **P2 cap-33 independent replication**: the second implementation gives `states = 235,809,128`, `levels = 457`, `complete = 1`, the identical length histogram, and no target hit — the same result as the ms14 engine (`evidence/P2_c33_replication_verification.json`, `verification_pass: true`).
- Certificates: the ms14 P1~C6 ledger (1066 moves, peak 41) is regenerated byte-for-byte from its path file; eight φ-bridge ledgers AK(3)~φ(AK(3)); all replay under our independent verifier and the official SAIR 14-move implementation (`verifier.core.apply_move`). New elementary ledgers found in this work: P1~φ₁(C6) (461 moves, peak 49) and C6~φ₁(C6) (1920 moves, peak 43) — both replay under the official implementation. (These do not improve the shortest known P1~C6 ledger.)

**(C) Machine-checkable closure certificate.** For AK(3) at cap 28 (`states = 8,694,374`) a sorted 128-bit canonical-key file plus a standalone checker: the checker regenerates all capped moves from scratch (238,806,300 moves), finds 0 violations, verifies the start class is present and the trivial presentation absent — certifying `B(AK(3)) >= 29` without re-running the search.

## 3. Limitations

- Every claim is **model-relative**: it concerns the SAIR 14-move model via the capped quotient model (with the published completeness condition). It is not a statement about arbitrary AC paths, Stable AC, or the general conjecture.
- The cap-33 enumerations were produced by the third-party ms14 engine (Apache-2.0, AI-generated, not peer reviewed). The second implementation's exact replication of the P1 run and the independent re-run of the model cross-checks are the essential checks; the P2 replication is recorded.
- The inference from an exhausted capped component to a peak lower bound relies on the projection/completeness argument documented in the ms14 repository; it is stated there but not formalized in a proof assistant. No new mathematical proof of that argument is claimed here.
- Novelty is relative to the public record as of 2026-11-12 (SAIR ACC Proof Track: 23 public submissions, none reporting cap-33; closest is ACC-P000012 by the ms14 authors with `>= 33` and self-labelled not independently verified; ms14 v2, census v2, arXiv and GitHub scans consistent). It cannot exclude private/unpublished work.
